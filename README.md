# DSH 私有数据档案

本仓库承载 DeepSeek Harness（DSH）固定档案网站。群聊、Issue 与 Repo 已停止采集并固定在 D1：访客可以阅读公共档案，只有群聊纪事和可能检索完整群聊的问答需要白名单成员登录。

> **群聊纪事与完整问答语料仅限获得授权的内部成员查看。** 公共星卡只展示已经过脱敏和逐卡复核的代表表现；不得把私有群聊纪事、完整语料或登录后检索结果转发到公开空间。

## 项目介绍

### 档案包含什么

- **今日最新**：按北京时间自然日展示群聊消息、主题、精选信号与当日创建的 Issue；
- **信号与纪事**：跨全部已归档自然日汇总可行动的问题、建议、实测与明确完成态事件；
- **成员星卡**：基于最终 66,187 条群消息重新逐卡复核全部实际发言成员；旧代表句不保留优先级，不推断真实身份；
- **Issue / Repo Board**：Issue 固定为最终版本；Repo 恢复并保留成员迁移前的 311 个完整仓库档案，按用途分组并解释“它是什么、最近发生了什么、为什么值得看”。

### 数据来源与边界

- 群聊只来自本机微信 4.x 数据库中的 `【官方】DSH内测群`；
- Issue 固定版本只来自私有仓库 `dsh-external/issues`；
- Repo 固定版本来自发布后成员迁移前、由已授权会话读取的 `dsh-external` 完整组织仓库列表；
- Repo 用途只依据 GitHub 仓库说明，最近动态只依据默认分支最新提交；阅读优先级由类别、创建时间和活跃度确定，不使用模型编造仓库能力；
- 页面不包含完整聊天记录、微信数据库、解密密钥、GitHub 凭据、本机配置或本机绝对路径；
- 历史 `corpus/` 与 `.local/` 只保留既有私有归档；封存后不再生成新群聊日、GitHub 同步或静态快照；
- 完整语料保留每条消息及其时间、发送者、左右归属、类型和正文，仅移除隐藏 XML/媒体密钥、凭据与本机绝对路径；
- 纪事收录产品方正式发布且来源可归属的信息，包括完成态更新、明确计划、仓库与工具发布、规则与服务公告；页面区分事件状态，成员疑问、转述与猜测不作为官方事实；
- 群聊统计窗口固定为北京时间 `00:00:00 <= timestamp < 次日 00:00:00`；页面显示最终固定截止点，不再暗示持续同步。

### 如何查看

- 外发网站：访客可直接访问 [`dsh.hiwangjie.com`](https://dsh.hiwangjie.com) 的公共档案；进入群聊纪事或使用问答时再登录；
- 网站默认展示最新完整群聊日，也可以从顶部日期选择器切换“今日最新”等日视图；成员星卡、信号、纪事与 Issue / Repo Board 始终展示当前全量数据，不随该日期切换；
- “新人导引”是独立固定内容入口，不随群聊日期切换；当前发布《DSH 内测安装指南（WSL2 Ubuntu 26.04）》，作者为 `@inschrift-spruch-raum`。

## 受保护网站

- 部署源是本私有仓库，但 Cloudflare Pages 只发布构建产生的 `dist/`。新数据从受保护 API 读取，完整私有语料不会进入 Pages；
- Pages 的高级模式 Function 位于所有网页和静态资源之前；GitHub OAuth 只读取公开账号身份，不申请 `read:org` 或其他组织权限；
- OAuth App 在 GitHub 中使用中性名称 `Member Portal`；成员首次授权后，它会出现在个人设置的 **Authorized OAuth Apps** 列表中，后续访问不需要重复同意同一组公开身份权限；
- 白名单成员 ID 保存在 Cloudflare D1。登录和后续访问按 GitHub ID 查询；未通过成员校验时不会读取群聊纪事或问答语料；
- GitHub OAuth 临时令牌只用于当次读取账号 ID，不写入页面、Cookie、D1 或仓库；首次授权后 GitHub 会记住该 OAuth App，网站签名会话保持 30 天，成员离开白名单后旧会话会立即失效；
- 站点响应禁止搜索引擎索引、禁止第三方页面嵌入，并关闭浏览器与边缘缓存；
- `npm run check` 先校验档案完整性和常见敏感路径/凭据，`npm run build` 再生成可部署目录；

### 成员名单更新

- GitHub 组织的 `organization` webhook 会把成员加入、移除事件即时写入 D1；成员接受邀请后无需等到 05:00，即可通过白名单门控。
- 匿名访问者打开成员入口时，系统会检查白名单新鲜度；超过 60 秒未全量核对时，会在后台从 GitHub API 重新读取完整组织成员，页面明确显示“正在同步访问名单”，通常需要 2–5 秒。
- 同一时间只允许一次全量刷新；新名单先写入 D1 暂存区，校验非空且计数一致后再原子切换。GitHub 或 D1 失败时保留上一版白名单，不让用户在名单未就绪时开始 OAuth。
- 后台全量刷新使用 Cloudflare 加密 Secret `GITHUB_ORG_READ_TOKEN`；该凭据只用于读取组织成员，不返回页面、不写入 D1 或仓库。终端用户 OAuth 仍只读取公开 GitHub 身份，不申请 `read:org`。
- 需要立即更新时，直接在 Codex 中说“同步 DSH 成员名单”即可；执行入口是 `npm run sync:members`，同步失败时不会用空名单覆盖现有白名单。
- 网站不向终端用户提供手工同步按钮；全量刷新只由后台冷却与单飞锁触发，防止匿名流量反复消耗 GitHub API 配额或频繁写入 D1。
- `latest.txt` 与历史静态 JSON 仅供本地迁移预览；生产首页必须读取 `CONTENT_DB` 的 active 日期与版本，接口失败时明确报错而不显示旧快照。

## 固定档案政策

- 群聊、Issue 与 Repo 的定时任务已经删除，本机 launchd 同步任务保持禁用；
- `refresh:group-day`、`sync:group-data`、`sync:github-data`、`backfill:content`、旧式 QA/快照入口均受代码冻结闸门保护，普通执行会直接拒绝；
- 页面每次打开只读取固定 D1 active，不再定时轮询、聚焦刷新、重建 Pages 或自动部署；
- `CONTENT_DB` 固定展示版本，`QA_DB` 固定完整检索版本，`ACCESS_DB` 仅用于成员门禁，三者不得混用；
- 未来如需改写档案，必须由用户明确授权一次代码发布，并重新执行完整暂存、计数、ID、隐私、FTS 与 active 指针校验。

## 本地问答预览

- 问答框位于“今日最新”顶部，从私有完整群聊、Issue 与 Repo 索引中检索，再把本轮命中的少量片段交给 DeepSeek；
- 复制 `.qa.local.env.example` 为不会被 Git 提交的 `.qa.local.env`，填写 `DEEPSEEK_API_KEY`；
- 当前默认模型为 `deepseek-v4-flash`，可通过 `DEEPSEEK_MODEL` 覆盖；Key 只由绑定在 `127.0.0.1` 的本机服务读取，不会进入浏览器、构建产物或仓库；
- 执行 `npm run dev:qa` 后访问终端显示的本地地址；该命令只启动本地预览，不会触发 Cloudflare 部署。

## 线上问答

- 线上 `/api/qa/status` 与 `/api/ask` 复用 GitHub 身份和组织成员白名单门禁，匿名请求无法读取状态、语料或调用模型；
- 完整群聊与 GitHub 固定数据使用两个独立 active 指针存放在私有 `QA_DB`。Issue API 与迁移前 Repo 的完整快照均采用分块版本存储；
- DeepSeek Key 只以 Cloudflare Pages 加密 Secret `DEEPSEEK_API_KEY` 保存。Worker 每轮只发送检索命中的少量片段，并按 GitHub 用户限制为每 10 分钟 20 次提问；
- 数据封存后，代码发布不得顺带运行任何群聊或 GitHub 数据任务。

## 文件命名与保留

每日数据使用 `snapshots/YYYY-MM-DD.json`，例如 2026 年 8 月 5 日为 `snapshots/2026-08-05.json`。历史日期分别保留，不覆盖旧快照。仓库根目录的两份按日 HTML 仅作为首轮迁移来源保留；后续自动任务不会再创建新的按日 HTML。

Private 仓库只能限制 GitHub 访问权限，不能阻止已获权限的人下载或继续转发文件。添加协作者前，请确认对方确实需要查看内测群内容。
